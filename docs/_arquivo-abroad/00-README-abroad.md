## Por que Spec Driven Development aqui

SDD normalmente organiza software em camadas: constituição (regras do jogo) → especificação (o quê e por quê) → plano (como) → tarefas (execução). Adaptei a mesma lógica para um projeto de negócio/pitch de uma semana:

## Como isso deve ser usado nas próximas conversas

1. No início de qualquer conversa nova sobre o projeto, eu releio estes arquivos antes de responder.
2. Nenhuma decisão relevante (problema escolhido, persona, modelo de negócio, cortes de escopo) fica só registrada no chat — ela é escrita no arquivo correspondente.
3. Os arquivos têm status (🔲 pendente / 🟡 em progresso / ✅ decidido) pra eu saber o que ainda está em aberto sem perguntar de novo.
4. Meu papel combinado com você: **sócio generalista** — cubro negócio, tech/IA, dados e pitch, questiono premissas e aponto o que a banca provavelmente vai perguntar.
